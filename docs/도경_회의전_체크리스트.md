# 도경 회의 전 체크리스트

## 1. 내 담당 범위

Notion 역할표와 단체 대화 기준으로 도경은 두 영역에 걸쳐 있습니다.

| 영역 | 함께하는 사람 | 도경 산출물 |
|---|---|---|
| 뼈대 개발 | 건호 | 일정 입력, 수면 계획 화면, 알림, 기본 데이터 흐름 |
| 개인화 기획 | 영민 | 입력 항목, 추천 규칙, 주간 업데이트 정책, 사용자 피드백 |

회의에서는 “화면만 만들었다”보다 아래 한 문장으로 설명하는 편이 좋습니다.

> 도경은 고정·변동 일정을 실제 추천 계산에 연결하고, 추천 근거와 아침 피드백이 다음 계획으로 이어지는 기본 데이터 흐름을 맡았습니다.

## 3. 회의에서 합의할 결정안

| 질문 | 도경 제안 | 이유 |
|---|---|---|
| 고정 일정 변경 시 자동 재계산? | 초기 3주는 자동, 이후에는 변경 미리보기 후 사용자 확인 | 예측 가능성과 개인 통제권을 함께 확보 |
| 목표 수면 시간을 요일별로 다르게 허용? | MVP는 공통 목표 1개, 이후 요일별 덮어쓰기 | 초기 입력 복잡도를 줄임 |
| 취침 시각을 범위로 표시? | 30분 범위 유지 | 하나의 실패 시각보다 현실적이며 기획 방향과 일치 |
| 수면을 충분히 확보할 수 없을 때? | 부족 시간과 다음 행동 1개를 표시하고 무리한 보충 수면은 강요하지 않음 | 웰니스 서비스의 안전한 표현 |
| 계획 실패 다음 날 처리? | 연속 기록 초기화 없이, 최근 3회 피드백에 따라 최대 30분만 조정 | 처벌보다 복귀를 돕는 서비스 원칙 |

## 4. 건호·영민과 맞출 API 초안

### 일정

```json
{
  "id": "schedule-id",
  "kind": "fixed | variable",
  "title": "전공 수업",
  "days": [1, 3],
  "date": "2026-08-07",
  "startTime": "09:00",
  "preparationMinutes": 40,
  "commuteMinutes": 50
}
```

- `fixed`는 `days`를 사용합니다. 일요일은 `0`, 토요일은 `6`입니다.
- `variable`은 `date`를 사용하며 해당 날짜 추천만 즉시 다시 계산합니다.

### 추천 결과

```json
{
  "targetDate": "2026-08-07",
  "wakeTime": "07:10",
  "bedtimeWindowStart": "23:01",
  "bedtimeWindowEnd": "23:31",
  "routineStart": "22:31",
  "reasons": ["09:00 수업과 통학·준비 시간을 반영했어요."],
  "alerts": [
    { "type": "routine", "time": "22:31" },
    { "type": "lights-out", "time": "23:01" },
    { "type": "wake", "time": "07:10" }
  ]
}
```

### 아침 피드백

```json
{
  "date": "2026-08-07",
  "actualSleep": "23:52",
  "actualWake": "07:25",
  "freshness": 3,
  "sleepiness": 2,
  "failureReason": "휴대폰 사용"
}
```

## 5. 90초 회의 시연 순서

1. 올빼미·박쥐 중 하나를 고르고 `내 리듬`에서 기상 시각·수면 길이·선택 캘린더를 설정합니다.
2. `오늘`에서 추천 근거와 12/24시간제 반영을 보여주고 불 끄기 시각을 5분 조절합니다.
3. `수면 시작`으로 잠금화면 Live Activity 목업을 엽니다.
4. 기상 알람에서 `알람 끄기`를 누르면 바로 기상 체크가 열리는 것을 보여줍니다.
5. 기상 체크 완료 후 꾸미기 포인트가 지급되는 것을 확인합니다.
6. `커뮤니티`에서 게시판, 공동 연속 일수, 12시 취침팟, 7일 50시간 도전을 보여줍니다.
