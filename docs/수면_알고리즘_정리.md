# 밤가이 수면 분석 및 추천 보정 알고리즘

## 1. 목적

밤가이의 수면 엔진은 사용자가 입력한 수면 기록과 주관적 피드백을 바탕으로 다음 목표 수면시간을 제안합니다.

- 실제 잠든 시각을 모르는 경우 `sleepOpportunityMinutes`를 사용합니다.
- 입면 지연을 입력하면 `estimatedSleepMinutes`로 보정합니다.
- 최근 기록을 Rule-Based로 분석합니다.
- 목표를 무조건 조금씩 늘리지 않고 `COARSE → FINE → MAINTENANCE` 순서로 탐색합니다.
- 의료적 진단이나 수면 점수를 제공하지 않습니다.

구현 파일:

```text
src/sleep-analysis.mjs
tests/sleep-analysis.test.mjs
```

`src/app.js` 경로의 앱 흐름:

```text
feedback 입력
→ sleep-analysis 분석
→ 필요하면 profile.targetSleepMinutes 갱신
→ planner가 새 목표로 취침 시각 계산
→ recommendation snapshot 저장
```

## 2. 입력 API

```js
const analysis = analyzeSleepHistory({
  profile,
  feedback,
  adaptationState,
});
```

`adaptationState`는 선택값입니다. 기존처럼 `profile`, `feedback`만 전달해도 동작합니다.

### feedback

기존 필드는 유지합니다.

```js
{
  date: "2026-08-12",
  actualSleep: "23:50",
  actualWake: "07:20",
  freshness: 3,
  sleepiness: 3,
  failureReason: "휴대폰을 오래 봄"
}
```

추가 선택 필드:

```js
{
  sleepOnsetDelayMinutes: 20,
  napDurationMinutes: 40,
  napReason: "졸려서"
}
```

입면 지연은 불을 끈 뒤 잠들기까지의 대략적인 시간입니다. 현재 UI는 0, 20, 45, 60, null 중 하나를 저장합니다. 낮잠 시간은 음수, NaN, 빈 값이면 null로 처리합니다.

## 3. 시간 계산

### 수면 가능 시간

```text
sleepOpportunityMinutes = actualWake - actualSleep
```

자정을 넘으면 다음 날 기상으로 계산합니다.

```text
23:50 → 07:20 = 450분
00:30 → 08:00 = 450분
```

취침·기상 시각이 같거나 시간 문자열이 잘못되면 해당 기록만 invalid 처리합니다.

### 추정 실제 수면 시간

```text
estimatedSleepMinutes =
  max(0, sleepOpportunityMinutes - sleepOnsetDelayMinutes)
```

입면 지연이 없으면 수면 가능 시간을 그대로 사용합니다. 이 값은 실제 수면 시간이 아니라 사용자 입력 기반 추정값입니다.

### 수면 부족

```text
rawSleepDeficitMinutes =
  targetSleepMinutes - estimatedSleepMinutes

sleepDeficitMinutes =
  max(0, rawSleepDeficitMinutes)
```

## 4. 분석 window

| 목적 | window |
|---|---:|
| 리포트·평균·중앙값·추세 | 최근 valid 7개 |
| Rule 판정·목표 조정 | 최근 valid 5개 |
| 새 목표 적용 평가 | 적용일 이후 valid 기록 |

원본 feedback 배열은 변경하지 않습니다.

## 5. 컨디션 신호

강한 신호:

```text
freshness <= 2
OR sleepiness >= 4
```

중간 컨디션 + 낮잠 신호:

```text
freshness === 3 AND napDurationMinutes >= 30
OR sleepiness === 3 AND napDurationMinutes >= 30
```

두 신호를 `conditionSuggestsMoreSleep(record)`로 판단합니다. 최근 5개 중 최소 3개가 신호를 보여야 목표를 조정합니다.

## 6. Rule 목록

### INSUFFICIENT_DATA

valid record가 3개 미만이면:

```js
{
  primaryState: "INSUFFICIENT_DATA",
  recommendedAction: "KEEP_COLLECTING_DATA",
  suggestedAdjustmentMinutes: 0,
  adjustmentPhase: "OBSERVE"
}
```

### INSUFFICIENT_SLEEP

최근 5개 중 3개 이상이 다음을 만족하면 발동합니다.

```text
sleepDeficitMinutes >= 30
AND conditionSuggestsMoreSleep(record)
```

단, 최근 5개의 평균 추정 수면이 현재 목표보다 30분 이상 부족하면 목표를 늘리지 않습니다.

```js
{
  recommendedAction: "REACH_CURRENT_TARGET",
  adjustmentStrategy: "REACH_CURRENT_TARGET",
  suggestedAdjustmentMinutes: 0
}
```

### LOW_CONDITION_DESPITE_DURATION

최근 5개 중 3개 이상이 다음을 만족하면 발동합니다.

```text
estimatedSleepMinutes >= currentTargetSleepMinutes - 15
AND conditionSuggestsMoreSleep(record)
```

현재 목표를 대체로 확보하지만 컨디션 저하가 반복되므로 목표 탐색 단계로 연결합니다.

### IRREGULAR_TIMING

최근 취침 시각의 circular range가 90분을 초과하면 발동합니다. 자정 경계를 포함한 최소 arc로 계산합니다.

### STABLE

다음 조건을 모두 만족하면 발동합니다.

```text
averageFreshness >= 4
averageSleepiness <= 2
averageSleepDeficitMinutes < 30
bedtimeRangeMinutes <= 90
```

결과:

```js
{
  recommendedAction: "KEEP_CURRENT_PLAN",
  adjustmentPhase: "MAINTENANCE",
  adjustmentStrategy: "KEEP_CURRENT_TARGET",
  suggestedAdjustmentMinutes: 0
}
```

### NO_CLEAR_PATTERN

3개 이상의 기록이 있지만 뚜렷한 Rule이 없을 때 반환합니다.

## 7. Coarse-to-Fine 목표 탐색

현재 목표를 대체로 달성하고 컨디션 저하 신호가 최근 5개 중 3개 이상 반복될 때만 목표를 늘립니다.

| 현재 목표 | 조정 | 단계 |
|---:|---:|---|
| 390분 미만 | +60분 | COARSE |
| 390~419분 | +30분 | COARSE |
| 420~479분 | +30분 | FINE |
| 480~539분 | +15분 | FINE |
| 540분 이상 | +0분 | OBSERVE |

최대 탐색 목표는 540분입니다. 의료 기준이 아니라 MVP 제품 보호용 상한입니다.

```js
recommendedTargetSleepMinutes = Math.min(
  540,
  Math.max(currentTargetSleepMinutes,
    currentTargetSleepMinutes + suggestedAdjustmentMinutes)
);
```

## 8. 탐색 상태와 평가 유예

목표를 변경한 뒤 같은 기록으로 다시 목표를 올리지 않습니다. 앱은 다음 상태를 localStorage에 저장합니다.

```js
adaptationState: {
  candidateTargetSleepMinutes: 420,
  previousTargetSleepMinutes: 360,
  evaluationStartDate: "2026-08-12",
  lastAdjustmentMinutes: 60
}
```

새 목표 적용 후 최소 3개의 valid record가 쌓일 때까지:

```js
{
  adjustmentPhase: "OBSERVE",
  adjustmentStrategy: "KEEP_CURRENT_TARGET",
  requiresEvaluation: true,
  canAdjustAgain: false
}
```

3개 이상의 평가 기록이 쌓이면 목표 유지, 다음 단계 증가, 현재 목표 확보, 다른 요인 관찰 중 하나를 다시 판단합니다.

## 9. recommendation snapshot

feedback 저장 시 그날 추천도 함께 저장합니다.

```js
recommendationSnapshot: {
  targetDate,
  bedtimeWindowStart,
  bedtimeWindowEnd,
  bedtimeCenter,
  wakeTime,
  targetSleepMinutes
}
```

이를 통해 추천 종료 시각과 실제 취침 시각의 차이를 계산할 수 있습니다.

```text
actualSleep - plannedBedtimeWindowEnd
```

## 11. planner 연결

새 엔진 결과를 planner에 연결할 때 기존 `planner.feedbackAdjustment()`와 중복 적용하면 안 됩니다.

```js
const analysis = analyzeSleepHistory({
  profile,
  feedback,
  adaptationState,
});

const planningProfile = {
  ...profile,
  targetSleepMinutes: analysis.recommendedTargetSleepMinutes,
};

calculateRecommendation({
  profile: planningProfile,
  schedules,
  feedback: [],
  targetDate,
});
```

`src/app.js` 경로는 새 분석 결과를 planner 입력에 반영하고, 기존 planner의 feedback 보정과 중복되지 않도록 feedback을 비워 전달합니다. 현재 `index.html`은 기존 `src/somni.js` 프로토타입을 진입점으로 유지하므로, 실제 브라우저 진입점 전환은 별도 팀 UI 작업에서 결정합니다.

## 12. 향후 Asleep 연동

objective 데이터가 들어오면 다음 우선순위를 사용합니다.

```text
objective totalSleepMinutes
→ estimatedSleepMinutes
→ sleepOpportunityMinutes
```

예상 확장 구조:

```js
objective: {
  sleepOnset,
  wakeTime,
  totalSleepMinutes,
  sleepEfficiency,
  awakenings
}
```

## 13. 현재 구현하지 않는 Rule

### REPEATED_LATE_EXECUTION

recommendation snapshot은 저장하기 시작했지만, 별도 Rule로는 아직 사용하지 않습니다. 충분한 snapshot이 쌓이면 다음 조건으로 추가할 수 있습니다.

```text
actualSleep > plannedBedtimeWindowEnd + 30분
최근 5회 중 3회 이상
```

### REPEATED_SLEEP_ONSET_DIFFICULTY

현재는 `sleepOnsetDelayMinutes`를 추정값으로 지원합니다. 반복적인 30분 이상 지연이 쌓이면 별도 Rule로 분리할 수 있습니다.

### SCHEDULE_CONFLICT

일정 때문에 수면 확보가 가능한지는 기존 planner의 책임으로 유지합니다.


현재 테스트는 시간 계산, invalid record, 평균·중앙값, 입면 지연, 낮잠 신호, 현재 목표 미달, +60/+30/+15 탐색, 540분 상한, STABLE 유지, mutation 방지 등을 검증합니다.

## 15. 주의사항

- `sleepOpportunityMinutes`는 실제 수면 시간이 아닙니다.
- `estimatedSleepMinutes`는 사용자 입력 기반 추정값입니다.
- `suggestedAdjustmentMinutes`는 의료적 처방이 아닙니다.
- 새 목표는 최소 3회 평가 기록 후 다시 조정합니다.
- 이 알고리즘은 설명 가능한 Rule-Based MVP입니다.
